# 충전 입구 분리 수정본

가져올 파일: `map_lay01_dist1_charging_split_v4.json`

기준은 사용자가 마지막으로 Export한 `map_lay01_dist1_89j.json`입니다.
원본, v3 파일, Workflow/Event와 로봇/화물의 현재 상태는 변경하지 않았습니다.

## 변경 내용

- 주 통로 62번과 64번의 Charging Entry 기능을 제거하고 일반 이동 노드로 바꿨습니다.
- 새 충전 입구 99번을 (11, 17), 100번을 (17, 17)에 추가했습니다.
- 왼쪽 분기: `62 — 1m — 99(충전 입구) — 1m — 88(충전소)`.
- 오른쪽 분기: `64 — 1m — 100(충전 입구) — 1m — 87(충전소)`.
- 충전소 88번과 87번의 입구 참조를 각각 99번과 100번으로 변경했습니다.
- 충전 방향, AMR 타입, 기존 충전기 식별자와 설정은 보존했습니다.
- 기존 27개 노드의 번호/UUID/좌표 및 작업장 10곳의 위치는 보존했습니다.
- 주 통로는 2m 간격을 유지합니다. 사용자가 선택한 대로 충전 접근 분기만 1m+1m입니다.
- 기존 대기 기능은 복구하지 않았습니다. 속도와 회전/주차 설정도 그대로입니다.

## 확인된 사실과 남은 확인

- 영상의 89↔97 이동은 62번을 피해 중앙을 경유하는 16m 경로와 일치합니다.
  맵의 정적 최단 경로는 12m입니다.
- SIM_CARGO_003은 영상에서 64번을 지나 94↔96을 왕복합니다.
  모든 충전 입구가 통과 금지됐다고 단정할 수 없습니다.
- 현재 맵에서 62번을 Move 목표로 선택하면 `Charge enter node can't be target node`가 표시됩니다.
  이는 일반 Move 목적지 제한이며, 통과 자체가 금지됐다는 증거는 아닙니다.
  62번을 일반 Move 목적지로 시험하라는 이전 안내는 잘못된 안내였습니다.
- 최신 맵은 v3와 연결/좌표/방향이 같고, 받은 WCS 로그에는 내부 경로 차단 이유가 없습니다.
- 이 수정은 주 통로에서 충전 입구 역할을 분리합니다. 실제 우회 감소와 충전 동작은
  Fleet에서 적용한 다음 확인해야 합니다. 동적 차단/Area/서버 정책은 이 파일에 포함되지 않습니다.

## 적용 순서

1. SIM_REPEAT_01/02/03을 Disable하고 현재 가상 작업이 완료되도록 기다립니다.
   별도로 남은 정지 미션이 있으면 Mission List에서 확인하고 취소합니다.
   맵 가져오기는 미션 취소나 들고 있는 화물 상태 초기화를 수행하지 않습니다.
2. 기존 `lay01 / dist1`에 수정 JSON을 Import하고 서버에 저장합니다.
   기존 Layout 자체를 삭제하거나 새 Layout을 만들지 않습니다.
3. 62/64가 일반 노드인지, 새 충전 입구가 99/100인지 확인합니다.
   일반 Move의 목표에는 62/64를 사용하고, 99/100은 충전 전용 입구로 사용합니다.
4. 1번 AMR로 왕복 1회 확인합니다. 정적 최단 경로는 다음과 같습니다.
   `89 → 68 → 65 → 62 → 59 → 56 → 97` 및 역방향, 편도 12m.
   실제 Fleet 경로는 장애물, 예약과 충돌 회피 조건에 따라 달라질 수 있습니다.
5. 1번 단독 운전에서도 62번을 계속 피한다면 해당 RCS 경로 계획 로그와 Area/차단 상태를
   확인해야 합니다. 이 경우 맵 변경만으로 원인이 해결됐다고 판단하지 않습니다.
6. 받은 `workflow-69.log`의 SIM_RT_03 설정에는 `robots: []`가 기록되어 있습니다.
   그 회차는 3번 AMR이 실행했지만 고정 배정은 아닙니다. 3대 담당을 고정하려면
   SIM_RT_03의 Robot ID에 3번을 명시한 뒤 저장합니다.
7. 왕복 확인 후 반복 이벤트를 다시 Enable하고 각 Workflow를 한 번씩 시작합니다.

## 정적 검증

- 노드 29개, 방향별 엣지 72개. 모든 엣지에 역방향 연결이 있습니다.
- 기존 노드의 신원/좌표와 관련 없는 설정은 보존됐습니다.
- 일반 통로 2m 엣지 64개, 충전 접근 1m 엣지 8개입니다(방향별 집계).
- 812개 방향별 노드 쌍의 정적 연결을 확인했습니다.
- 충전 전용 노드 99/100/87/88을 모두 제외해도 세 운반 구간이 연결됩니다.
- 편도 정적 최단 거리: 89↔97 12m, 84↔86 12m, 94↔96 8m.
- SDK가 인식하는 필드의 파싱을 확인했습니다. native UI export의 일부 필드는 SDK에 없어
  전체 native Import 검증과 동일한 검증은 아닙니다.
- 실제 Fleet Import/가상 주행/충전과 실물 간섭은 아직 검증하지 않았습니다.
