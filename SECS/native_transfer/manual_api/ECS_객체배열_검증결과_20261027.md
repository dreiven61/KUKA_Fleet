# ECS 객체 배열 전송 검토 결과

검토일: 2026-10-27

## 결론

현재 검토한 ECS의 `Grpc api call → external system` 요청 본문 편집·생성 경로에서는 `missionData` 같은 객체 배열을 구성하여 전송하는 방법이 확인되지 않았다. UI 타입 목록과 Import 변환기에 배열 처리가 없고, 서버 본문 생성기의 ARRAY 분기도 없다. INTEGER의 특수 배열 처리는 `List<Integer>` 전용이다.

이는 이 경로의 구현 제한에 대한 검증 결과다. 모든 Fleet 버전이나 모든 SECS 연계 방식이 불가능하다는 결론은 아니다. 공식 지원 방법 및 수정 버전 유무는 KUKA의 확인이 필요하다.

## 검토 대상과 근거 범위

- 사용자 환경: KUKA.AMR Fleet 2.15.1, 기존 KMP1500i 가상 AMR 유지.
- 규칙: `SecsTransferTest` Export JSON.
- 현재 웹 서버에서 받은 `ruleDetail--Zy6BsBk.js`는 로컬 분석 파일과 내용이 동일했다(HTTP 200, 내용 비교 일치).
- 서버 Registry의 현재 `ecs-engine:kmres` 이미지 config digest는 로컬 ECS 추출본과 동일했다.
  - `sha256:3c37fc383cd94a6d2f27ff00e853e37b8ea8422bd3507dd5ad632a95e94afbeb`
- 분석한 ECS 라이브러리: `rule-engine-components-2.11.0.jar`, `rule-engine-api-2.11.0.jar`, `data-2.11.0.jar`, `ecs-application.jar`.
- 위 2.11.0은 라이브러리 버전이며 Fleet 제품 버전과 같은 의미로 사용하지 않았다.
- 실행 컨테이너의 Image ID는 비대화식 sudo로 조회하지 못했다. Registry 이미지 일치를 실행 컨테이너의 Image ID 확인으로 대신 주장하지 않는다.

## 확인 결과

| 대상 | 실제 확인 결과 |
|---|---|
| UI 타입 목록 | `BaseDataController.getJsonDataTypes`는 STRING, NUMBER, INTEGER, BOOLEAN, OBJECT만 반환한다. ARRAY는 반환하지 않는다. |
| UI Import | 실제 프런트엔드의 `importSetData`를 로컬에서 실행했다. `missionData`, `robotIds`, `robotModels`의 type이 빈 문자열이고 children은 빈 목록이 됐다. |
| ARRAY로 본문 생성 | 실제 `HttpApiCallHelper.assembleJson`을 실행하면 해당 필드가 요청에서 누락된다. |
| STRING으로 JSON 입력 | 배열처럼 보이는 문자열로 남는다. JSON 배열로 변환되지 않는다. |
| INTEGER + 기존 배열 값 | 값이 `[1,2]`일 때만 정수 배열로 전달되는 특수 처리가 있다. 내부 타입은 `TypeToken<List<Integer>>`다. |
| INTEGER + 객체 배열 값 | `Expected an int but was BEGIN_OBJECT` 예외가 재현됐다. 운송 노드 객체 배열 전달에 사용할 수 없다. |
| SECS 수신값 | 현재 Export의 수신 스키마는 DATAID, OBJSPEC, RCMD 및 COMMANDID, PRIORITY, REPLACE, CARRIERID, SOURCEPORT, DESTPORT를 받는다. 운송 객체 배열을 만드는 설정은 없다. |
| 다른 외부 시스템 호출 경로 | 검토한 `NodeCallGrpcHandler`의 레거시 외부 시스템 경로는 MODBUS, S7, HTTP만 허용하고 다른 전송 타입에 PROTOCOL_MISMATCH를 반환한다. 현재 E82 장치의 직접 대체 경로로 확인되지 않았다. |

일반 API 호출 노드는 설치 매뉴얼 5.13.2.8(490~491쪽)에 설명되어 있으나, 해당 설명에서 객체 배열 작성 방법은 찾지 못했다. 문서에 설명이 없다는 사실만으로 미지원이라고 판단한 것은 아니며, 위 실제 코드 실행 결과를 함께 근거로 삼았다.

## 운송 API 자체는 성공

2026-10-27 사용자가 API 문서 Debug 화면에서 운송 JSON을 직접 전송했다. 이후 읽기 전용 조회로 다음을 확인했다.

- 작업: `API_TR_20261027_001`
- 가상 AMR: 1번
- 컨테이너: `SIM_CARGO_001`
- 출발: `lay01-dist1-89`
- 도착: `lay01-dist1-97`
- `jobQuery`: status 30, completeTime 존재, spendTime 51, warnFlag 0.
- `robotQuery`: 97번, 빈 적재 상태, `noError-idle`.
- `containerQuery`: `SECS_ST_97`, isCarry 0.

따라서 남은 검토 대상은 ECS에서 동일한 객체 배열 본문을 구성하는 부분이다. 운송 API 접수 성공과 SECS 자동 연계 완료를 혼동하면 안 된다.

## 로컬 재현 파일

- `C:\work\KUKA\tmp\rcs_native_link_inspect\CheckSecsRequestArray.java`: 실제 설치 라이브러리를 호출한 5개 본문 생성 사례. 예상된 누락·문자열 유지·객체 배열 예외 및 정수 배열 성공을 검증했다.
- `C:\work\KUKA\tmp\rcs_native_link_inspect\CheckEcsJsonImport.cjs`: 실제 UI Import 메서드를 추출하여 운송 JSON을 변환했다. 배열 3개 필드가 구성되지 않는 것을 검증했다.
- 두 재현 프로그램은 로컬 실행만 하며 HTTP 운송 요청, DB 기록, 로봇 동작을 수행하지 않는다.

## KUKA 확인 요청 문구

KUKA.AMR Fleet 2.15.1의 기존 KMP1500i New Sims를 유지하면서, ECS E82 장치에서 받은 S2F49 TRANSFER의 SOURCEPORT/DESTPORT로 픽업·드롭 운송을 생성하려 합니다. Standard API 2.15.5의 submitMission에 객체 배열 missionData를 직접 전송한 운송 시험은 완료되었습니다.

현재 ECS의 Grpc api call → external system 경로에서는 UI 타입 목록에 ARRAY가 없고, JSON Import 시 배열 필드의 타입과 내부 구조가 생성되지 않습니다. 서버 HttpApiCallHelper.assembleJson도 ARRAY 항목을 생성하지 않으며, INTEGER 경로의 배열 처리는 List<Integer> 전용이라 객체 배열에는 예외가 발생합니다.

1. 이 설치 버전에서 missionData와 같은 중첩 객체 배열을 전송하는 공식 설정 방법 및 Export 예제가 있습니까?
2. 지원 패치나 후속 ECS 빌드가 있다면 적용 가능한 버전과 해당 수정 내역을 알려주십시오.
3. 해당 경로에서 지원하지 않는 경우, 외부 브릿지 없이 기존 KMP1500i New Sims에 S2F49 TRANSFER의 From/To를 연결하는 권장 Fleet 내부 연계 방식을 알려주십시오.

이 문구는 문의 초안이며 외부로 발송하지 않았다. 인증 토큰은 포함하지 않았다.
