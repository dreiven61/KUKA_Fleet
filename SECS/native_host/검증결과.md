## 검증한 경계

- 실제 API 접수 HCACK4, 기존ID HCACK5, 명시적 거부 HCACK2, 파라미터 오류 HCACK3/CPACK, 미지원명령1, 미등록대상6.
- API 응답 유실은 UNCERTAIN으로 보존하고 거짓 거부 ACK나 운송 재시도 없음.
- CANCEL=NORMAL, 픽업 시작 이전만 허용. ABORT=FORCE, 픽업 시작 관찰 이후만 허용.
- 제어 API 접수만으로 완료 보고 없음. 취소 callback 성공/실패에 따라201/204 또는202/205. 실패 시 원래 운송 유지.
- 일시중지는 실제 TASK_SUSPENDED 이후209/105, 재개는 실제 실행 callback 이후210/103. 첫 PAUSE의 명시적 거부 시 AUTO 유지.
- 제어 전송 중 응답 유실·재시작을 중복 제어 재실행으로 복구하지 않음.
- 경로 WARNING은 알람이며 비정상 종료가 아님. 실제 실패 TASK_COMPLETED 이후에만207 nonzero. 시험 Result9000과 명시적 interlock 매핑을 구분.
- S5F1/S5F2의 실제 루프백 발생·해제 송수신 및 U4 ALID900001 확인. CEID702/701 후속 보고 확인.
- S6F12=1 실제 수신 후 BLOCKED. 명시적 보고 재시도에서 같은 DATAID 사용.
- 보고 ACK를 버리고 실제 소켓 단절/재접속 후 미보고604 재전송. 운송 API는 여전히1회.
- 서버 저널 재로드 후 중복ID 거부와 미보고 DATAID 유지.
- Java와 .NET의 서로 다른 SECS 구현을 연결해 S1F13/14, S2F49/50(HCACK4), 기존14개 S6F11/S6F12 순서·최종207 확인. 실제 API는 루프백 mock이다.
- WPF 연결되지 않은 상태에서는 운송·CANCEL/ABORT/PAUSE/RESUME 버튼 비활성화.10개 포트와 신규 버튼 렌더링 확인.

## 확인되지 않은 부분

실제 Fleet1.0.0 설치/포트 노출, 실제 CANCEL/ABORT callback 및 화물 잔류, 실제 PAUSE/RESUME, 실제 PP_NoPath 발생·해제는 사용자 적용 후 확인해야 한다. 모의 callback 시험 통과가 현장 동작 성공을 의미하지 않는다. 실제 네트워크 단절 중 누락된 WCS 통지는 재구성하지 않는다.

전체 SKI/GEM 인증, 일반 설비 알람101/102, WCS에 없는 하드웨어 알람, 다중 화물·HA·저널 자동 정리까지 완료한 것이 아니다. 승인된 ALID900001과 일반 실패 Result9000은 시험 프로파일이며 SKI 공식 할당값이 아니다.

설치 SECS2.11.0의 timed wait 함수와 Passive 상태 프로퍼티에 관찰된 동작 차이는 공급사 코드를 패치하지 않고 호출부에서 처리했다. 실제 선택된 세션 채널을 확인하며 생산 코드에서 결함이 있는 timed wait 함수를 사용하지 않는다.
