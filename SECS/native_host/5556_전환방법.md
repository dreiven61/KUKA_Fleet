# 기존 5556 주소 유지 — 현재 적용 절차

2026-10-28. 플러그인 **1.1.1**, Virtual MCS **2.1.1**.

앞으로 PC는 **192.168.0.45:5556 / Active / Session3000**으로 연결한다.
새 컨테이너나 별도 PC 브릿지를 만들지 않는다. 기존 Interface Platform 안의 플러그인으로 처리한다.
5557은 이전 개발본의 주소이며 현재 적용 절차에 사용하지 않는다.

## 실제 서버 조회 결과

- `kecs-engine`: Docker `5556:5556` 게시 중.
- `kuka-interface`: `10870:10870`만 게시 중. 기존 로그 볼륨 `${LOG_HOME}:/var/log/kuka` 사용.
- `/opt/server/config/servostar-secs.json` 없음. 플러그인의 SECS 수신부는 설정 없이 열리지 않는다.
- 서버 5556은 수신 대기 중이고 5557은 수신 대기하지 않는다.

따라서 **PC 포트 숫자만 바꿔서는 새 기능을 쓸 수 없다.** 외부 주소5556은 그대로 유지하면서, 그 주소의 수신 담당을 ECS에서 플러그인으로 한 번 옮겨야 한다. 서버 변경은 자동 실행하지 않았다.

## 1. 기존 작업과 기록 보존

기존 운송을 정상 완료/정리하고 Virtual MCS·SEComSimulator의 연결을 끊는다. Equipment → Device의 `MES_SECS_TEST`는 Disable한다. 다른 ECS 장치나 반복 이벤트를 삭제하지 않는다.

서버에서 compose 파일을 백업한다.

```bash
cd /opt/server
sudo cp -a docker-compose.yml "docker-compose.yml.bak.$(date +%Y%m%d_%H%M%S)"
```

기존 플러그인의 운송 관찰 저널은 컨테이너 재생성 전에 반드시 확인·보존한다.

```bash
if sudo docker exec kuka-interface test -f /opt/nav/robot/bin/Log/interface/servostar-transfer-journal.jsonl; then
  sudo docker cp kuka-interface:/opt/nav/robot/bin/Log/interface/servostar-transfer-journal.jsonl "$HOME/servostar-transfer-journal.before-5556.jsonl"
fi
```

파일이 있으면 위 명령이 사용자 홈으로 백업한다. 백업이 실패하면 컨테이너를 재생성하지 않는다.

Docker 재생성으로 미확인 COMMANDID 기록이 사라지지 않도록, 아래 로그 볼륨의 `interface/servostar-transfer-journal.jsonl` 위치에 기존 파일을 보존한 뒤 진행한다. 다른 기록이 이미 있으면 덮어쓰거나 두 파일을 임의 합치지 않는다. Native Host 기존 journal이 있다면 그것도 백업한다. 새 저널로 시작해 미확인 작업을 재발행하지 않는다.

## 2. 설정 파일 준비

Windows PowerShell에서 실행한다. 이미 사용하던 토큰은 로컬 전용 설정 파일에 유지했으며 포트만5556, 저널 경로는 기존 로그 볼륨 안으로 맞췄다. 토큰이 포함된 파일을 외부에 공유하지 않는다.

```powershell
scp "C:\work\KUKA\SECS\native_host\servostar-secs_READY_LOCAL_WITH_TOKEN.json" servostar@192.168.0.45:~/servostar-secs.json
```

서버에서 컨테이너 실행 계정으로 설정을 설치한다.

```bash
plugin_uid=$(sudo docker exec kuka-interface id -u)
plugin_gid=$(sudo docker exec kuka-interface id -g)
sudo mkdir -p /opt/server/config
sudo install -o "$plugin_uid" -g "$plugin_gid" -m 0640 ~/servostar-secs.json /opt/server/config/servostar-secs.json
sudo install -d -o "$plugin_uid" -g "$plugin_gid" -m 0750 /opt/server/logs/interface
```

이미 서버 설정 파일이 생겼다면 먼저 백업하고 authorization/journal을 비교한다. 기존 Native Host journal이 있으면 새 경로로 임의 초기화하지 말고 기존 파일을 보존한다.

1단계에서 관찰 저널이 백업됐다면 기존 로그 볼륨에 복원한다. 현재 조회에서는 아래 호스트 경로에 파일이 없었다. 이후 파일이 생겼다면 덮어쓰지 말고 비교한다.

```bash
if sudo test -f "$HOME/servostar-transfer-journal.before-5556.jsonl"; then
  if sudo test -e /opt/server/logs/interface/servostar-transfer-journal.jsonl; then
    echo "중지: 기존 호스트 저널을 먼저 비교하세요. 덮어쓰지 않습니다."
  else
    sudo install -o "$plugin_uid" -g "$plugin_gid" -m 0640 "$HOME/servostar-transfer-journal.before-5556.jsonl" /opt/server/logs/interface/servostar-transfer-journal.jsonl
  fi
fi
```

중지 메시지나 복원 오류가 나오면 다음 단계로 진행하지 않는다.

## 3. 같은5556의 수신 담당만 교체

`/opt/server/docker-compose.yml`에서 두 서비스만 편집한다.

**kecs-engine**의 다음 항목을 제거한다.

```yaml
ports:
  - "5556:5556"
```

현재 조회상 이 서비스의 게시 포트는5556 하나다. 다른 포트가 추가됐다면 그것은 유지하고5556 줄만 제거한다. `kecs-engine` 서비스를 삭제하거나 전체 ECS를 중지하는 작업은 아니다.

**kuka-interface**에는 기존 항목을 유지하며 다음처럼 병합한다. `ports`와 `volumes` 키를 두 번 만들지 않는다.

```yaml
ports:
  - "10870:10870"
  - "5556:5556"
volumes:
  - ${LOG_HOME}:/var/log/kuka
  - ${PLUGIN_HOME}:/workspace/plugins:z
  - /opt/server/config/servostar-secs.json:/opt/nav/config/servostar-secs.json:ro
  - ${LOG_HOME}:/opt/nav/robot/bin/Log:z
```

마지막 항목은 이미 사용 중인 호스트 로그 폴더를 기존 TransferJournal 경로에도 연결한다. 새 Native Host 기록은 `/var/log/kuka/interface/servostar-native-state.json`에 저장하므로 별도 상태 폴더·컨테이너는 만들지 않는다. 기존 `${LOG_HOME}/interface`와 저널 파일의 소유자를 현재 plugin_uid/plugin_gid가 읽고 쓸 수 있게 확인한다. 기존 로그 전체 소유자를 재귀 변경하지 않는다.

검증 후 **먼저 기존5556 게시를 해제하고**, 다음에 새 게시를 만든다. 두 컨테이너 재생성 중 통신이 잠시 끊긴다. kecs-engine 재생성 중에는 다른 ECS 장치 연결도 잠시 끊길 수 있으므로 장치 작업을 정리한 상태에서 진행한다.

```bash
cd /opt/server
sudo docker compose config --quiet
sudo docker compose up -d --no-deps kecs-engine
sudo docker compose up -d --no-deps kuka-interface
```

`config --quiet`가 실패하면 다음 명령을 실행하지 않는다. `docker restart`만으로 포트 매핑이 바뀌지 않는다. 로봇 제어 컨테이너는 재시작하지 않는다.

## 4. 새 플러그인과 PC 실행

1. Fleet 웹에 다시 로그인한다. STANDARD-API는 유지한다.
2. 현재 SERVOSTAR-MES-TRANSFER만 Disable하고 `C:\work\KUKA\SECS\fleet_transfer_plugin\build\servostar-mes-transfer-1.1.1.jar`을 Import → Enable → STARTED 확인한다. 이전 버전을 함께 Enable하지 않는다.
3. 서버 로그에서 `Native SECS passive listener started on 5556, session 3000`을 확인한다.

   ```bash
   sudo docker logs --tail 80 kuka-interface
   sudo docker ps --filter name=kuka-interface --format 'table {{.Names}}\t{{.Ports}}'
   ```

4. `C:\work\KUKA\VirtualMCS\실행.cmd` 또는 `dist-2.1.1\KukaVirtualMCS.exe` 실행.
5. PC 주소192.168.0.45 / Port5556 / Active / Session3000 / T3 120초 확인 → 연결. 자동 접속이나 자동 운송은 없다.
6. S1F14의 장비 모델 FLEET, 버전1.1.1과 COMMUNICATING을 확인한다. 예전 ECS 응답 `MDLN-A / 000001`이면 아직 구 수신부에 연결된 것이다. 새 화물 명령을 보내지 말고 포트 게시와 플러그인 활성 상태부터 확인한다.
7. 우선 **Fleet 화물 조회**만 누른다. CEID9001과 목록이 수신되면 화물 입출고 시험으로 넘어간다. 자세한 동작 순서는 `화물입출고_적용방법.md`를 참고한다.

PC2.1.1은 저장 설정 중 이 Fleet의5557만5556으로 표시값을 옮긴다. 다른 IP/임의 포트/Session/연결 모드는 유지한다. 저장 파일은 연결 버튼을 누를 때 저장하며, 실행 중인 이전 창을 자동으로 종료하거나 교체하지 않는다.

## 되돌릴 경우

미확인 입출고·운송을 먼저 확인한다. 새 플러그인 수신과 연결을 정리한 뒤 kuka-interface의5556 게시를 제거하고, 백업을 참조해 kecs-engine의5556 게시를 복구한다. 동시에 두 서비스가 같은 호스트5556을 게시하지 않도록 한다. 기존 ECS 장치는 필요할 때만 다시 Enable한다. 새 버전 기록을 삭제해 명령을 다시 보내지 않는다.
