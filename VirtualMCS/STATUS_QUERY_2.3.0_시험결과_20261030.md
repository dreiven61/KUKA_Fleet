# Virtual MCS 2.3.0 상태 조회 시험 화면

2026-10-30 KST. Fleet 플러그인1.3.0 / 192.168.0.45:5556 / Session3000. 기존 SIM01 KMP1500I3대 유지. 실제 WPF 배포 프로그램으로 접속하고 UI 버튼을 눌러 검증했다. 별도 Python HSMS 호스트의 이전 시험과 구분한다.

## 추가된 화면

- 메인 **상태 조회 시험** 버튼: AGV·관리 포트·현재 작업·화물 목록, 요청별 응답 시간·성공/실패·SML 원문을 표시한다.
- **접속 후 상태 조회**: 체크 시 통신 확립 후 SVID25→58→23을 응답 대기 없이 자동 요청한다. 재접속 후에도 다시 실행한다. 자동 접속·운송 발행은 하지 않는다.
- 개별 조회,4종 묶음 조회,전체SVID 조회,L0 요청을 지원한다.
- **연속 요청 시험**: 기본100묶음/300요청. 묶음 내3개 요청은 응답 대기 없이 보내며 다음 묶음은 이전3개 응답 후 시작한다. 최대1000묶음. 중지 가능.
- 단절 시 목록을 무효화한다. S1F0·잘못된 본문·조회 실패를 성공한 빈 작업 목록으로 바꾸지 않는다. 원문과 조회 결과는 기존 로그 폴더에도 저장한다.

S1F0·잘못된 S1F4 실패 처리는 localhost 모의 응답으로 검증했다. 이번 GUI 시험에서 실제 운송 중 목록·리프트 동작·ACK 장애를 새로 유도하지 않았다. 현재 작업이0건인 실제 조회와 미확인 작업을 포함한 로컬 파서 검증을 구분한다. 종전 Fleet6903/6904 운송 단절 시험은 [서버1.3.0 시험 결과](../SECS/native_host/RECONNECT_1.3.0_시험결과_20261030.md)에 있다.

최종 UI만 원문 상단 정렬을 수정하여 재게시했다. 코드·로컬 검사는 동일하고 최종 배포본에서도 자동 조회·전체 조회·묶음 조회·재접속을 확인했다. 서버 프로그램과 설정은 이번 작업에서 변경하지 않았다.

## 사용

1. `실행.cmd` 또는 `dist-2.3.0/KukaVirtualMCS.exe` 실행.
2. 메인 화면에서 **접속 후 상태 조회** 체크 후 **연결**.
3. **상태 조회 시험**을 열어 자동 조회 결과 확인.
4. 개별 조회 또는 **연속 요청 시험** 실행. 아래 로그 행을 선택하면 오른쪽에 요청·응답 원문이 나온다.
5. **로그 폴더 열기**로 `%LOCALAPPDATA%\ServoStar\KukaVirtualMCS\logs`에 저장된 날짜별 원문 로그 확인.
