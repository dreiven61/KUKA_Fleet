# KUKA Fleet 가상 AMR 3대 자동 운반

`시뮬레이션_실행안내.html`을 열고 **실행 코드 복사** → 로그인된 Fleet 탭의 **F12 → Console**에 붙여넣기 → 화면 오른쪽 아래 **① 3대·트레이 준비 → ② 왕복 시작**.

| 가상 AMR | 시작 노드 | 왕복 구간 | 가상 트레이 |
|---|---:|---|---|
| 90101 | 68 | 89 ↔ 97 | SIM_CARGO_001 |
| 90102 | 69 | 84 ↔ 86 | SIM_CARGO_002 |
| 90103 | 67 | 94 ↔ 96 | SIM_CARGO_003 |

현재 지도 `lay01 / dist1`, 모델 `SIM_TRAY_001`을 사용한다. 레이아웃은 사용자가 Fleet에서 활성화해야 하며 프로그램이 자동 활성화하지 않는다. 로봇 타입은 서버의 실제 KMP1500i 코드와 크기를 조회한다. 기존 ID나 트레이 코드와 충돌하면 기존 데이터를 덮어쓰지 않는다.

3대는 Fleet 내장 시뮬레이터에서 생성한다. 실제 운반은 Fleet Monitor의 Carry 명령과 같은 `/apimm/api/mission/dispatch`, `T1`을 사용한다. 따라서 Job Board의 WCS Workflow가 아니라 **Mission List / Monitor**에 표시된다. 별도 WCS Workflow를 생성하거나 실물 로봇을 등록하지 않는다. 자동 충전은 이 프로그램에 포함하지 않는다.

반복 정지는 **새 명령 발행만 중지**한다. 이미 전달된 명령은 Fleet에서 계속된다. 명령을 취소하거나 강제 완료하지 않는다. 탭을 닫거나 새로고침하면 반복 제어가 끝난다. 브라우저가 백그라운드 타이머를 제한하면 다음 명령 발행이 지연될 수 있다.

로그인 토큰은 Fleet 페이지의 기존 localStorage에서 읽어 동일 Fleet 서버에만 보낸다. 토큰·비밀번호를 코드, 다운로드, 로그에 기록하지 않는다. 가상 로봇/트레이 식별자, 준비 단계, 운반 작업 번호, 완료 횟수만 Fleet origin의 localStorage에 보존한다. 이 프로그램을 실행한 브라우저의 해당 기록을 임의로 삭제하지 않는다.

응답 유실 시 이미 기록한 `upstreamNumber`로 결과부터 조회한다. 성공 응답만으로 완료 처리하지 않는다. `FINISHED` 상태, 도착 트레이 위치, 내려놓음, AMR 유휴 상태가 함께 확인된 후 다음 작업을 발행한다. 실행 중 로그인 만료/미확정/시간 초과가 나면 새 작업을 중단하고 작업 번호를 남긴다. 다른 브라우저에서 같은 ID를 다시 만들거나 동일 미션을 새 번호로 재전송하지 않는다.

## 검증 범위

`node test_simulation.cjs`로 가상 생성, 재실행, 3대 왕복, 실물 차단, ID 충돌, 응답 유실, 완료 판정, 정지를 모의 서버에서 검사했다. 실제 Fleet 인증 세션을 이용한 생성·운반은 아직 검증하지 않았다. 최초 실행 오류는 제어창에 표시되는 원문으로 확인한다.

실제 장비 안전 검증이나 경로 적합성 검증을 대신하지 않는다. 현재 지도 90번 부근은 장애물과 가까워 기본 왕복 구간에서 제외했다.
